## Protocol Overview

The Agent-to-Agent (A2A) protocol is designed to enable standardized communication between independent AI agents. It addresses a critical challenge in enterprise AI adoption: getting agents built on different frameworks and by different vendors to work together effectively.

### Key Features

- **Framework Agnostic**: Works with any agent framework or implementation
- **Standardized Communication**: Provides a common language for agents to communicate
- **Capability Discovery**: Allows agents to discover and leverage each other's capabilities
- **Secure Communication**: Built with enterprise security requirements in mind
- **Flexible Interaction**: Supports various interaction modes (text, forms, files, etc.)
- **Asynchronous Processing**: Handles long-running tasks with streaming updates and push notifications

### Design Philosophy

A2A is built on several key design principles:

1. **Opaque Agents**: Agents are treated as "black boxes" with well-defined interfaces
2. **Task-Oriented**: Communication is centered around task completion
3. **Stateful Interactions**: Tasks maintain state and history
4. **Extensible Format**: The protocol can be extended to support new capabilities
5. **Enterprise Ready**: Designed with security, scalability, and reliability in mind

## Key Components

The A2A protocol consists of several key components:

### Agent Card

A public metadata file (usually at `/.well-known/agent.json`) that describes an agent's:
- Capabilities and skills
- Endpoint URL
- Authentication requirements
- Supported input/output modes

The Agent Card serves as the primary mechanism for agent discovery and capability advertisement.

### A2A Server

An agent exposing an HTTP endpoint that implements the A2A protocol methods. The server:
- Receives task requests
- Processes tasks
- Manages task state
- Generates artifacts
- Sends updates to clients

### A2A Client

An application or another agent that consumes A2A services. The client:
- Discovers agent capabilities
- Initiates tasks
- Sends messages
- Receives updates and artifacts
- Manages task state locally

### Task

The central unit of work in A2A. A task:
- Has a unique identifier
- Maintains state (submitted, working, input-required, completed, failed, canceled)
- Contains messages between client and server
- Stores artifacts generated by the agent
- Can be long-running and asynchronous

### Message

Represents communication turns between the client (`role: "user"`) and the agent (`role: "agent"`). Messages:
- Contain one or more parts
- Have a specific role (user or agent)
- Can include metadata

### Part

The fundamental content unit within a Message or Artifact. Parts can be:
- **TextPart**: Plain text content
- **FilePart**: Binary data with a MIME type (inline or via URI)
- **DataPart**: Structured JSON data (e.g., forms)

### Artifact

Outputs generated by the agent during a task. Artifacts:
- Can be named and described
- Contain one or more parts
- Are immutable
- Can be streamed in chunks

## Communication Flow

The typical communication flow in A2A follows these steps:

1. **Discovery**: Client fetches the Agent Card from the server's well-known URL
2. **Initiation**: Client sends a task request with an initial message
3. **Processing**: Server processes the task and updates its state
4. **Updates**: Server sends status updates and artifacts to the client
5. **Interaction**: Client sends additional messages if the task requires input
6. **Completion**: Task reaches a terminal state (completed, failed, canceled)

### Communication Methods

A2A supports several communication methods:

- **Synchronous Request/Response**: For simple, quick tasks
- **Polling**: Client periodically checks task status
- **Server-Sent Events (SSE)**: Server streams updates to connected clients
- **Push Notifications**: Server sends updates to a webhook URL for disconnected clients

## Task Lifecycle

Tasks in A2A progress through a defined lifecycle:

1. **Submitted**: Task has been received by the server but processing hasn't started
2. **Working**: Server is actively processing the task
3. **Input-Required**: Server needs additional information from the client
4. **Completed**: Task has been successfully completed
5. **Failed**: Task encountered an error and couldn't be completed
6. **Canceled**: Task was canceled by the client or server

Each state transition can trigger notifications to the client, allowing for real-time updates on task progress.

## Message Structure

Messages in A2A follow a structured format:

```json
{
  "role": "user",  // or "agent"
  "parts": [
    {
      "type": "text",
      "text": "Hello, can you help me with a task?"
    },
    {
      "type": "file",
      "file": {
        "name": "document.pdf",
        "mimeType": "application/pdf",
        "bytes": "base64-encoded-content"
      }
    },
    {
      "type": "data",
      "data": {
        "form": {
          "name": "John Doe",
          "email": "john@example.com"
        }
      }
    }
  ],
  "metadata": {
    "timestamp": "2023-06-15T14:30:00Z"
  }
}
```

This structured format allows for rich, multi-modal communication between agents.

## Agent Discovery

A2A provides mechanisms for agents to discover each other and their capabilities:

### Well-Known URL

Agents typically publish their Agent Card at a well-known URL:
```
https://example.com/.well-known/agent.json
```

### Agent Card Format

The Agent Card contains detailed information about the agent:

```json
{
  "name": "Example Agent",
  "description": "An example agent that demonstrates A2A capabilities",
  "url": "https://example.com/a2a",
  "version": "1.0.0",
  "capabilities": {
    "streaming": true,
    "pushNotifications": true
  },
  "authentication": {
    "schemes": ["Bearer"]
  },
  "defaultInputModes": ["text/plain", "application/json"],
  "defaultOutputModes": ["text/plain", "application/json"],
  "skills": [
    {
      "id": "weather",
      "name": "Weather Information",
      "description": "Provides weather forecasts for locations",
      "tags": ["weather", "forecast"],
      "examples": ["What's the weather in San Francisco?"]
    }
  ]
}
```

This information allows clients to understand what the agent can do and how to interact with it.
