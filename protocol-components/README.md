## Agent Card

The Agent Card is a JSON document that describes an agent's capabilities, skills, and requirements. It serves as the primary mechanism for agent discovery and capability advertisement.

### Structure

```json
{
  "name": "Example Agent",
  "description": "An example agent that demonstrates A2A capabilities",
  "url": "https://example.com/a2a",
  "provider": {
    "organization": "Example Corp",
    "url": "https://example.com"
  },
  "version": "1.0.0",
  "documentationUrl": "https://example.com/docs",
  "capabilities": {
    "streaming": true,
    "pushNotifications": true,
    "stateTransitionHistory": true
  },
  "authentication": {
    "schemes": ["Bearer"],
    "credentials": "optional-credentials-for-private-cards"
  },
  "defaultInputModes": ["text/plain", "application/json"],
  "defaultOutputModes": ["text/plain", "application/json"],
  "skills": [
    {
      "id": "weather",
      "name": "Weather Information",
      "description": "Provides weather forecasts for locations",
      "tags": ["weather", "forecast"],
      "examples": ["What's the weather in San Francisco?"],
      "inputModes": ["text/plain"],
      "outputModes": ["text/plain", "application/json"]
    }
  ]
}
```

### Fields

- **name**: Human-readable name of the agent
- **description**: Description of what the agent does
- **url**: Endpoint URL for A2A protocol requests
- **provider**: Information about the organization providing the agent
- **version**: Version of the agent
- **documentationUrl**: URL to documentation for the agent
- **capabilities**: Optional capabilities supported by the agent
  - **streaming**: Whether the agent supports SSE streaming
  - **pushNotifications**: Whether the agent supports push notifications
  - **stateTransitionHistory**: Whether the agent exposes status change history
- **authentication**: Authentication requirements
  - **schemes**: Authentication schemes supported (e.g., "Basic", "Bearer")
  - **credentials**: Optional credentials for private cards
- **defaultInputModes**: MIME types supported for input
- **defaultOutputModes**: MIME types supported for output
- **skills**: Array of skills the agent can perform
  - **id**: Unique identifier for the skill
  - **name**: Human-readable name of the skill
  - **description**: Description of what the skill does
  - **tags**: Categories or keywords for the skill
  - **examples**: Example prompts for the skill
  - **inputModes**: MIME types supported for this skill (overrides defaults)
  - **outputModes**: MIME types supported for this skill (overrides defaults)

### Discovery

Agent Cards are typically published at a well-known URL:
```
https://example.com/.well-known/agent.json
```

This allows clients to discover agents and their capabilities through a standard mechanism.

## Task

A Task is the central unit of work in A2A. It represents a stateful entity that allows clients and agents to collaborate on achieving a specific outcome.

### Structure

```json
{
  "id": "task-123",
  "sessionId": "session-456",
  "status": {
    "state": "working",
    "message": {
      "role": "agent",
      "parts": [{"type": "text", "text": "Processing your request..."}]
    },
    "timestamp": "2023-06-15T14:30:00Z"
  },
  "history": [
    {
      "role": "user",
      "parts": [{"type": "text", "text": "What's the weather in San Francisco?"}]
    }
  ],
  "artifacts": [
    {
      "name": "weather-data",
      "description": "Current weather in San Francisco",
      "parts": [
        {
          "type": "data",
          "data": {
            "temperature": 72,
            "conditions": "sunny"
          }
        }
      ],
      "index": 0
    }
  ],
  "metadata": {
    "custom-field": "custom-value"
  }
}
```

### Fields

- **id**: Unique identifier for the task
- **sessionId**: Optional identifier for grouping related tasks
- **status**: Current status of the task
  - **state**: State of the task (submitted, working, input-required, completed, failed, canceled)
  - **message**: Optional message providing additional context
  - **timestamp**: When the status was last updated
- **history**: Array of messages exchanged during the task
- **artifacts**: Array of artifacts generated by the agent
- **metadata**: Optional custom metadata

### Task States

- **submitted**: Task has been received but processing hasn't started
- **working**: Agent is actively processing the task
- **input-required**: Agent needs additional information from the client
- **completed**: Task has been successfully completed
- **failed**: Task encountered an error and couldn't be completed
- **canceled**: Task was canceled by the client or agent

### Task Events

For streaming and push notifications, tasks generate events:

```json
{
  "id": "task-123",
  "status": {
    "state": "working",
    "timestamp": "2023-06-15T14:30:05Z"
  },
  "final": false
}
```

```json
{
  "id": "task-123",
  "artifact": {
    "name": "weather-data",
    "parts": [{"type": "data", "data": {"temperature": 72}}]
  }
}
```

## Message

A Message represents a communication turn between the client and the agent. It contains content in the form of Parts.

### Structure

```json
{
  "role": "user",
  "parts": [
    {
      "type": "text",
      "text": "What's the weather in San Francisco?"
    },
    {
      "type": "file",
      "file": {
        "name": "location.json",
        "mimeType": "application/json",
        "bytes": "eyJsYXQiOjM3Ljc3NDksImxvbmciOi0xMjIuNDE5NH0="
      }
    }
  ],
  "metadata": {
    "timestamp": "2023-06-15T14:30:00Z"
  }
}
```

### Fields

- **role**: Either "user" (client) or "agent" (server)
- **parts**: Array of content parts
- **metadata**: Optional custom metadata

## Part

A Part is a piece of content within a Message or Artifact. A2A supports three types of parts:

### TextPart

```json
{
  "type": "text",
  "text": "What's the weather in San Francisco?",
  "metadata": {
    "format": "markdown"
  }
}
```

### FilePart

```json
{
  "type": "file",
  "file": {
    "name": "document.pdf",
    "mimeType": "application/pdf",
    "bytes": "base64-encoded-content"
  },
  "metadata": {
    "size": 1024
  }
}
```

Alternatively, files can be referenced by URI:

```json
{
  "type": "file",
  "file": {
    "name": "document.pdf",
    "mimeType": "application/pdf",
    "uri": "https://example.com/files/document.pdf"
  }
}
```

### DataPart

```json
{
  "type": "data",
  "data": {
    "temperature": 72,
    "conditions": "sunny",
    "location": "San Francisco"
  },
  "metadata": {
    "schema": "weather-v1"
  }
}
```

## Artifact

An Artifact represents an output generated by the agent during a task. Artifacts are immutable and can contain multiple parts.

### Structure

```json
{
  "name": "weather-report",
  "description": "Current weather conditions in San Francisco",
  "parts": [
    {
      "type": "text",
      "text": "It's currently 72°F and sunny in San Francisco."
    },
    {
      "type": "data",
      "data": {
        "temperature": 72,
        "conditions": "sunny",
        "location": "San Francisco"
      }
    }
  ],
  "index": 0,
  "append": false,
  "lastChunk": true,
  "metadata": {
    "source": "National Weather Service"
  }
}
```

### Fields

- **name**: Optional name for the artifact
- **description**: Optional description of the artifact
- **parts**: Array of content parts
- **index**: Position in the list of artifacts (0-based)
- **append**: Whether this artifact should append to an existing artifact with the same index
- **lastChunk**: Whether this is the final chunk of a streaming artifact
- **metadata**: Optional custom metadata

### Streaming Artifacts

For large artifacts, A2A supports streaming in chunks:

1. First chunk: `{"index": 0, "append": false, "lastChunk": false, ...}`
2. Middle chunks: `{"index": 0, "append": true, "lastChunk": false, ...}`
3. Final chunk: `{"index": 0, "append": true, "lastChunk": true, ...}`

This allows for efficient transmission of large artifacts like generated images or documents.

## Push Notification

Push Notifications allow agents to notify clients of task updates when they're not actively connected.

### Configuration

```json
{
  "url": "https://example.com/webhook",
  "token": "notification-token-123",
  "authentication": {
    "schemes": ["Bearer"],
    "credentials": "auth-token-456"
  }
}
```

### Fields

- **url**: Webhook URL where notifications should be sent
- **token**: Optional token unique to this task/session
- **authentication**: Optional authentication requirements for the webhook

### Notification Format

Notifications are sent as HTTP POST requests to the webhook URL:

```json
{
  "id": "task-123",
  "status": {
    "state": "completed",
    "timestamp": "2023-06-15T14:35:00Z"
  },
  "final": true
}
```

## JSON-RPC Methods

A2A defines several JSON-RPC methods for client-server communication:

### tasks/send

Sends a message to an agent to create, continue, or restart a task.

**Request:**
```json
{
  "jsonrpc": "2.0",
  "id": "request-123",
  "method": "tasks/send",
  "params": {
    "id": "task-123",
    "sessionId": "session-456",
    "message": {
      "role": "user",
      "parts": [{"type": "text", "text": "Hello"}]
    },
    "historyLength": 10,
    "pushNotification": {
      "url": "https://example.com/webhook"
    }
  }
}
```

**Response:**
```json
{
  "jsonrpc": "2.0",
  "id": "request-123",
  "result": {
    "id": "task-123",
    "sessionId": "session-456",
    "status": {"state": "working"},
    "history": [{"role": "user", "parts": [{"type": "text", "text": "Hello"}]}]
  }
}
```

### tasks/sendSubscribe

Similar to tasks/send but establishes an SSE connection for streaming updates.

**Request:**
```json
{
  "jsonrpc": "2.0",
  "id": "request-123",
  "method": "tasks/sendSubscribe",
  "params": {
    "id": "task-123",
    "message": {
      "role": "user",
      "parts": [{"type": "text", "text": "Hello"}]
    }
  }
}
```

**Response (SSE stream):**
```
event: message
data: {"jsonrpc":"2.0","id":"request-123","result":{"id":"task-123","status":{"state":"working"}}}

event: message
data: {"jsonrpc":"2.0","id":"request-123","result":{"id":"task-123","status":{"state":"completed","message":{"role":"agent","parts":[{"type":"text","text":"Hello! How can I help you?"}]}},"final":true}}
```

### tasks/get

Retrieves the current state of a task.

**Request:**
```json
{
  "jsonrpc": "2.0",
  "id": "request-123",
  "method": "tasks/get",
  "params": {
    "id": "task-123",
    "historyLength": 10
  }
}
```

**Response:**
```json
{
  "jsonrpc": "2.0",
  "id": "request-123",
  "result": {
    "id": "task-123",
    "status": {"state": "completed"},
    "history": [
      {"role": "user", "parts": [{"type": "text", "text": "Hello"}]},
      {"role": "agent", "parts": [{"type": "text", "text": "Hello! How can I help you?"}]}
    ]
  }
}
```

### tasks/cancel

Attempts to cancel a task.

**Request:**
```json
{
  "jsonrpc": "2.0",
  "id": "request-123",
  "method": "tasks/cancel",
  "params": {
    "id": "task-123"
  }
}
```

**Response:**
```json
{
  "jsonrpc": "2.0",
  "id": "request-123",
  "result": {
    "id": "task-123",
    "status": {"state": "canceled"}
  }
}
```

### tasks/pushNotification/set

Configures push notifications for a task.

**Request:**
```json
{
  "jsonrpc": "2.0",
  "id": "request-123",
  "method": "tasks/pushNotification/set",
  "params": {
    "id": "task-123",
    "pushNotificationConfig": {
      "url": "https://example.com/webhook",
      "token": "notification-token-123"
    }
  }
}
```

**Response:**
```json
{
  "jsonrpc": "2.0",
  "id": "request-123",
  "result": {
    "id": "task-123",
    "pushNotificationConfig": {
      "url": "https://example.com/webhook",
      "token": "notification-token-123"
    }
  }
}
```

### tasks/pushNotification/get

Retrieves the push notification configuration for a task.

**Request:**
```json
{
  "jsonrpc": "2.0",
  "id": "request-123",
  "method": "tasks/pushNotification/get",
  "params": {
    "id": "task-123"
  }
}
```

**Response:**
```json
{
  "jsonrpc": "2.0",
  "id": "request-123",
  "result": {
    "id": "task-123",
    "pushNotificationConfig": {
      "url": "https://example.com/webhook",
      "token": "notification-token-123"
    }
  }
}
```

### tasks/subscribe

Subscribes to updates for an existing task.

**Request:**
```json
{
  "jsonrpc": "2.0",
  "id": "request-123",
  "method": "tasks/subscribe",
  "params": {
    "id": "task-123"
  }
}
```

**Response (SSE stream):**
```
event: message
data: {"jsonrpc":"2.0","id":"request-123","result":{"id":"task-123","status":{"state":"working"}}}

event: message
data: {"jsonrpc":"2.0","id":"request-123","result":{"id":"task-123","status":{"state":"completed"},"final":true}}
```
